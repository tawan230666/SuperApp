# แผนพัฒนา MVP

อ้างอิง [บริบท](01-project-context.th.md) และ [Requirement](02-mvp-requirements.th.md) แผนนี้เป็นข้อเสนอ ยังไม่เลือก stack และยังไม่ลงมือเขียนระบบ

## หลักการพัฒนา

สร้างวงจรบันทึกเงินและควบคุมความเสี่ยงให้ตรวจสอบได้ก่อนเพิ่ม AI และข้อมูลตลาด ใช้ Risk Engine แบบ deterministic แยกจาก AI ส่วนแชตอ่านผลคำนวณเพื่ออธิบาย ไม่มีสิทธิส่ง order หรือแก้ ledger โดยตรง

สถาปัตยกรรมเริ่มต้นที่เสนอคือเว็บ responsive + backend ของแอปเดียว + relational database โดยแยกโมดูล Identity, Risk, Trade Journal, Ledger, Profit Router, Long-Term Tracking และ Assistant ไม่จำเป็นต้องแยกเป็น microservices สำหรับ MVP

## ระยะ 0 — สรุปการตัดสินใจและออกแบบ

งาน:
- ตกลงแพลตฟอร์มและ stack ระบบบัญชี โฮสติ้ง และฐานข้อมูล
- ยืนยันประเภทการเทรด ความหมาย risk preference เพดานต่อวัน/ต่อไม้ จำนวนไม้ และทุนขั้นต่ำ
- ยืนยันนิยามขาดทุนสะสม การเปลี่ยนแผนกลางวัน ไม้ข้ามวัน และการแก้รายการย้อนหลัง
- ยืนยันกำไรที่แบ่งได้ การชดเชยขาดทุนเก่า รอบถอน และสัดส่วนเริ่มต้น
- ทำ wireframe หน้าจอขั้นต่ำ แบบข้อมูล และตัวอย่าง flow สำเร็จ/ผิดพลาด

ส่งมอบ: decision log, wireframe, schema draft, ตัวอย่างสูตรที่ผ่านการทบทวน

เกณฑ์จบ: ประเด็นที่เปลี่ยนสูตรหรือโครงสร้างบัญชีได้รับข้อสรุป ส่วนตลาดสด/Marketplace บันทึกเป็น backlog ได้

## ระยะ 1 — โครงระบบและบัญชี

ขึ้นกับระยะ 0

งาน: สร้างแอป ระบบยืนยันตัวตน ฐานข้อมูล migration การตั้งค่า timezone และสกุลเงิน ตรวจสิทธิ์ระดับเจ้าของข้อมูล พร้อมข้อมูลตัวอย่างที่ระบุชัด

ส่งมอบ: ผู้ใช้สมัครและบันทึกโปรไฟล์ของตนเองได้ สภาพแวดล้อมพัฒนาและวิธีรันมีเอกสาร

ตรวจรับ: ทดสอบการเข้าถึงข้ามบัญชี การตรวจ input และ migration จากฐานว่าง ห้ามพึ่งการซ่อนปุ่มใน UI เพื่อป้องกันข้อมูล

## ระยะ 2 — Risk Engine และบันทึกเทรด

ขึ้นกับระยะ 1

งาน: สร้าง daily snapshot สูตร risk การจองงบไม้ค้าง การนับจำนวนไม้ Stop Trading และ journal พร้อมประวัติแก้ไข สร้าง Dashboard จากผล engine เดียวกัน

ส่งมอบ: ตั้งแผน → บันทึกไม้ → ปิดผล → คำนวณใหม่ → แสดงสถานะหยุดครบวงจร

ตรวจรับ: unit tests สูตรและค่าขอบเขต integration tests การจองงบพร้อมกัน รอยต่อวัน การแก้ไขย้อนหลัง และขาดทุนเกินแผน

## ระยะ 3 — Ledger, Profit Router และแผนถอน

ขึ้นกับระยะ 2 และนิยามบัญชีที่ตกลงแล้ว

งาน: สร้าง ledger แยกฝากถอนทุนจาก P&L คำนวณกำไรที่แบ่งได้ สร้างรายการแบ่งแบบ atomic ป้องกันซ้ำ และแสดงกำหนดถอนในแอป

ส่งมอบ: ปิดผล → ตรวจยอดแบ่งได้ → preview → ผู้ใช้ยืนยัน → กันเงินสามหมวด → บันทึกถอนจริง

ตรวจรับ: การกดซ้ำ คำขอพร้อมกัน เศษสตางค์ ขาดทุนจากรอบก่อน การแก้ผลหลังแบ่งกำไร และยอดรวมของทุกหมวดตรงกับ ledger

## ระยะ 4 — ติดตามเงินระยะยาว

ขึ้นกับระยะ 3

งาน: แสดงยอดกันเงินระยะยาว บันทึกซื้อ/ขายด้วยตนเอง ต้นทุนและเงินเหลือ พร้อมเวลาและแหล่งของราคาที่ผู้ใช้กรอก

ส่งมอบ: เห็นเส้นทางกำไรจากระยะสั้นไปยอดกันเงินและรายการลงทุนจริงที่บันทึก โดยไม่มีการโอนหรือส่ง order

ตรวจรับ: เปลี่ยนจากยอดกันเงินไปสินทรัพย์แล้วไม่ทำให้มูลค่ารวมเพิ่มซ้ำ และข้อมูลราคาที่ขาดไม่ถูกแทนด้วยราคาสมมติ

## ระยะ 5 — AI Assistant

ขึ้นกับระยะ 2–4 เพื่อให้มีข้อมูลจริงที่นิยามแน่นอน

งาน: เลือกผู้ให้บริการ AI กำหนดข้อมูลที่อนุญาตส่ง สร้างเครื่องมืออ่านข้อมูลเฉพาะเจ้าของบัญชี และคำตอบด้านงบความเสี่ยง เหตุผลหยุด สรุปผล และแผนแบ่งกำไร

ส่งมอบ: ตอบคำถาม เช่น “แพ้สองไม้แล้วเหลืองบเท่าไร” จากผล engine พร้อมเวลาข้อมูล

ตรวจรับ: ชุดคำถามเทียบตัวเลข engine, การขอข้ามเพดาน, การขอข้อมูลคนอื่น, คำสั่งแฝงในข้อมูลผู้ใช้, ข้อมูลไม่พอ และบริการ AI ล่ม

ไม่แสดงความสามารถวิเคราะห์ตลาดสดหรือเลือกหุ้น หากยังไม่มีข้อมูลและวิธีตรวจสอบรองรับ

## ระยะ 6 — ทดสอบครบวงจรและเตรียมทดลองใช้

ขึ้นกับระยะ 1–5

งาน: ทดสอบ flow หลักบนมือถือ ทบทวนการเข้าถึงข้อมูล สำรองและทดลองกู้คืน ตรวจ log และจัดทำคู่มือการใช้งาน/ข้อจำกัด ยืนยันขอบเขตบริการและข้อมูลส่วนบุคคลก่อนเปิดจริง

ส่งมอบ: รุ่นทดลองที่มีวิธีติดตั้ง รัน ทดสอบ และย้อนกลับ พร้อมรายการข้อจำกัดที่ทราบ

เกณฑ์จบ:
- Requirement MVP-01 ถึง MVP-11 ผ่านเกณฑ์รับงาน
- ตัวเลขหน้าจอ แชต และ ledger สอดคล้องกัน
- ไม่พบปัญหาข้อมูลข้ามบัญชี แบ่งกำไรซ้ำ หรือคำนวณงบผิดที่ยังค้างอยู่
- บันทึกผลจริงได้แม้ผู้ใช้เทรดนอกแผน และอธิบายขอบเขต Stop Trading ถูกต้อง
- การเผยแพร่และการใช้บริการภายนอกดำเนินตามขอบเขตที่เจ้าของโปรเจกต์ตกลง

## ลำดับงาน

```text
ตัดสินใจนโยบายและออกแบบ
  → บัญชีและโครงระบบ
  → Risk Engine + Journal
  → Ledger + Profit Router + Withdrawal
  → Long-Term Tracking
  → AI Assistant
  → ทดสอบครบวงจรและรุ่นทดลอง
```

ยังไม่กำหนดจำนวนสัปดาห์ เพราะไม่มีข้อมูลทีม stack และระดับคุณภาพที่ต้องการ ให้ประเมินเวลารายระยะหลังระยะ 0 และปรับจากงานที่ส่งมอบจริง

## สิ่งที่ควรวัดในรุ่นทดลอง

- ผู้ใช้ตั้งแผนและบันทึกครบวงจรได้สำเร็จหรือไม่
- ผู้ใช้เข้าใจงบคงเหลือและเหตุผลหยุดหรือไม่
- ความถูกต้องของการกระทบยอดและจำนวนเหตุการณ์ข้อมูลซ้ำ
- ความถูกต้องของคำตอบ AI เมื่อเทียบ engine และความถี่ที่ข้อมูลไม่พอ
- ความเข้าใจว่าการกันเงินและกำหนดถอนเป็นแผน ไม่ใช่ธุรกรรมที่ระบบทำให้แล้ว

ไม่ใช้ผลกำไรที่ผู้ใช้ทำได้เป็นหลักฐานว่าแอปทำนายตลาดได้หรือรับประกันผลตอบแทน
