# บริบทหลักของโปรเจกต์

บันทึกวันที่ 6 กันยายน 2026 จากรายละเอียดที่เจ้าของโปรเจกต์ให้ในบทสนทนา เอกสารชุดนี้เป็นฐานสำหรับออกแบบและพัฒนา ยังไม่มีการเริ่มเขียนแอป

## สถานะที่ตรวจพบ

ตรวจโฟลเดอร์ `/Users/tawan/Project/SuperApp` รวมไฟล์ซ่อนแล้วพบว่าเป็นโฟลเดอร์ว่าง ไม่มีซอร์สโค้ด package manifest เอกสาร การทดสอบ `.git` หรือ `AGENTS.md` และไม่พบ `AGENTS.md` ในโฟลเดอร์แม่ที่ตรวจ ดังนั้นยังไม่มีเทคโนโลยีหรือสถาปัตยกรรมเดิมให้ต่อยอด เอกสารชุดนี้สร้างใหม่โดยไม่มีการเขียนทับไฟล์เดิม

## วิสัยทัศน์ที่ยืนยันแล้ว

**AI Investment Risk & Wealth Management Application** ช่วยวางแผนเงินลงทุนระยะสั้น คุมความเสี่ยง บันทึกผล แบ่งกำไร วางแผนถอน และนำส่วนหนึ่งไปสร้างพอร์ตระยะยาว โดย AI เป็นผู้ช่วยตัดสินใจและอธิบายข้อมูล

วงจรที่ต้องการคือ เงินตั้งต้น → วางแผนความเสี่ยง → ลงทุนระยะสั้น → ประเมินผลและหยุดตามเงื่อนไข → แบ่งกำไร → ถอน/กันเงิน → สะสมพอร์ตระยะยาว วงจรนี้เป็นกระบวนการจัดการเงิน ไม่ใช่คำยืนยันว่าจะมีกำไรหรือเพิ่มทุนได้เสมอ

แกนผลิตภัณฑ์: AI ช่วยให้ผู้ใช้รู้ว่าเมื่อไรควรเสี่ยง หยุด ถอน และย้ายเงินไปลงทุนระยะยาว ไม่ใช่ทำให้ชนะทุกวัน

## ข้อกำหนดที่ยืนยันแล้ว

- มีบัญชีผู้ใช้ ข้อมูลทุน และโปรไฟล์ความเสี่ยง โดยแยกความชอบรับความเสี่ยงออกจากเงินจริงที่อนุญาตให้เสี่ยง
- มี Risk Engine คำนวณงบความเสี่ยงต่อวัน ต่อไม้ จำนวนไม้สูงสุด และเงื่อนไขหยุด
- เป้าหมายกำไรเป็นเป้าหมาย ไม่ใช่ผลตอบแทนรับประกัน
- มีบันทึกการลงทุนและผลลัพธ์ เพื่อสรุปพฤติกรรมและผลการลงทุน
- มี Profit Router แบ่งกำไรเป็นทุนระยะสั้น เงินสำหรับระยะยาว และเงินสำหรับถอน
- รองรับแผนถอนรายวัน รายสัปดาห์ หรือรายเดือน และแนวคิดป้องกันกำไรกลับไปเสี่ยงทั้งหมด
- มีภาพรวมพอร์ตระยะยาวและ AI Assistant ที่ใช้ข้อมูลบัญชีของผู้ใช้ในการตอบ
- ออกแบบไม่ผูกกับโบรกเกอร์รายเดียว ชื่อ IQ Option และ Dime เป็นตัวอย่างจากแนวคิด ไม่ใช่การยืนยันการเชื่อมต่อหรือการรับรองแพลตฟอร์ม
- ขอบเขตเริ่มต้นไม่รับฝากเงิน ไม่ถือเงินแทนผู้ใช้ และไม่ส่งคำสั่งซื้อขาย ผู้ใช้ตัดสินใจและดำเนินการเอง
- การวิเคราะห์ตลาดและหุ้นระยะยาวเป็นส่วนหนึ่งของวิสัยทัศน์ โดยอธิบายเหตุผลและความเสี่ยง ไม่รับประกันผลตอบแทน
- สคริปต์ซื้อขายในอนาคตต้องอยู่ภายใต้ Risk Engine
- โมเดลรายได้ที่สนใจคือ Subscription, Script Marketplace และรายได้จากพันธมิตร ทั้งหมดยังไม่ใช่ข้อผูกมัดในการเปิดใช้ MVP

## ตัวเลขสมมติ ห้ามใช้เป็นค่าจริงโดยปริยาย

| ตัวอย่างจากแนวคิด | สถานะและสิ่งที่ต้องระวัง |
|---|---|
| ทุน 350 บาท | ตัวอย่างทุนขั้นต่ำที่กำลังพิจารณา ต้องปรับตั้งได้หากเลือกใช้ |
| ระดับความเสี่ยง 20/30/50/60/100% | ตัวอย่างป้ายโปรไฟล์ ไม่ใช่สัดส่วนลงเงินต่อไม้ ต้องกำหนดความหมายใหม่ให้ชัดก่อนพัฒนา |
| Risk ต่อวัน 5% = 17.50 บาท | ตัวอย่างการคำนวณ ไม่ใช่ระดับความเสี่ยงที่แนะนำ |
| Risk ต่อไม้ 5 บาท และสูงสุด 3 ไม้ | ใช้ได้ในตัวอย่างงบ 17.50 บาท หากไม่มีความเสี่ยงอื่นหรือไม้ค้าง |
| Target 10/20/30 บาท และเฉลี่ย 10 บาทต่อไม้ | ตัวอย่างเท่านั้น ไม่ได้พิสูจน์ว่าเป็นไปได้จากสินทรัพย์และผลตอบแทนจริง |
| Loss Limit 20 บาท และ Risk ต่อไม้ 5–7 บาท | ไม่สอดคล้องกับงบ 17.50 บาทในอีกตัวอย่าง ห้ามนำมารวมเป็นนโยบายเดียวโดยไม่ตัดสินใจ |
| แบ่งกำไร 50/30/20% หรือระยะยาว 40% | เป็นคนละตัวอย่าง ยังไม่มีสัดส่วนเริ่มต้นที่ยืนยัน |
| ถอนทุกวันอาทิตย์ | ตัวอย่างกำหนดการรายสัปดาห์ |
| กำไร 500 บาท ย้าย 300 บาท เหลือ 200 บาท | ตัวอย่าง Profit Protection ยังไม่ใช่กฎอัตโนมัติ |
| AI Confidence 68% | ตัวอย่างหน้าจอ ไม่ใช่โอกาสชนะที่ผ่านการสอบเทียบ |
| พอร์ต 1,000 บาท แบ่ง 300/250/300/150 | ตัวอย่างการจัดสรร ไม่ใช่คำแนะนำลงทุนจริง |

## ประเด็นที่ยังต้องตัดสินใจ

| เรื่อง | ข้อเสนอสำหรับเริ่มต้น | ผลต่อการพัฒนา |
|---|---|---|
| แพลตฟอร์ม | เว็บ responsive ภาษาไทย | กำหนด UI และการเผยแพร่ |
| ประเภทสินทรัพย์/การเทรด | เริ่มจากรายการที่ระบุขาดทุนสูงสุดได้ | มีผลต่อสูตร risk, ค่าธรรมเนียม และกรณีขาดทุนเกินแผน |
| นโยบาย risk | ใช้สูตรกำหนดแน่นอนและเพดานที่ตกลงก่อนพัฒนา | ต้องกำหนด daily risk, per-trade risk และจำนวนไม้ |
| นิยามขาดทุนรายวัน | ใช้ยอดขาดทุนสะสมแยกจากกำไร | ป้องกันกำไรมาปลดงบให้เสี่ยงเพิ่ม ต้องยืนยันนโยบายนี้ |
| ทุนขั้นต่ำ/ยอดขั้นต่ำของแพลตฟอร์ม | ปรับตั้งได้และไม่เสนอไม้เมื่อขั้นต่ำเกินงบ | ไม่ควรฝืนให้ทุนเล็กเทรดได้ทุกแพลตฟอร์ม |
| รอบกำไรที่แบ่งได้ | กำไรสุทธิหลังชดเชยขาดทุนเดิมและหักส่วนที่แบ่งแล้ว | ต้องตกลงนิยามฐานเงินและรอบบัญชี |
| เวลา | เสนอ Asia/Bangkok สำหรับ MVP | กำหนดวันเทรด รอบถอน และรายการย้อนหลัง |
| AI | เริ่มจากอธิบายข้อมูลจริงและกฎที่ตรวจสอบได้ | ผู้ให้บริการ งบค่าใช้จ่าย และขอบเขตข้อมูลยังไม่เลือก |
| ตลาดและหลักทรัพย์ | เลื่อนข้อมูลสดและการจัดอันดับหุ้น | ต้องเลือกแหล่งข้อมูล สิทธิใช้งาน ความถี่ และวิธีประเมิน |
| บัญชีและข้อมูลส่วนตัว | ใช้ระบบยืนยันตัวตนมาตรฐาน | ต้องเลือกผู้ให้บริการ ระยะเก็บข้อมูล การลบบัญชี และนโยบายข้อมูล |
| กฎหมายและรายได้ | ตรวจตามรูปแบบบริการจริงก่อนเปิดความสามารถที่เกี่ยวข้อง | เอกสารนี้ยังไม่ได้ตรวจข้อกฎหมายหรือสถานะโบรกเกอร์ ณ ปัจจุบัน |

รายละเอียดที่ระบุว่า “เสนอ” ในเอกสารชุดนี้เป็นทางเลือกออกแบบ ยังไม่ใช่การตัดสินใจของเจ้าของโปรเจกต์
