# Requirement สำหรับ MVP

อ้างอิง [บริบทหลัก](01-project-context.th.md) ขอบเขตและสูตรด้านล่างเป็นข้อเสนอ MVP ที่นำวิสัยทัศน์มาจัดลำดับ ยังต้องยืนยันนโยบายที่ระบุไว้ก่อนใช้กับเงินจริง

## ผลลัพธ์ของ MVP

ผู้ใช้หนึ่งคนสามารถตั้งทุนและแผนความเสี่ยง บันทึกผลด้วยตนเอง เห็นเหตุผลว่าควรหยุดหรือยังมีงบเหลือ แบ่งกำไรโดยไม่ซ้ำ และติดตามเงินที่กันไว้สำหรับถอนหรือระยะยาวได้ครบวงจร

ยอดทั้งหมดเป็นข้อมูลบันทึกเพื่อวางแผน ไม่ใช่ยอดเงินที่แอปถืออยู่ คำว่า Long-Term Wallet ในแนวคิดให้ใช้ชื่อ “เงินที่กันไว้ลงทุนระยะยาว” ใน MVP เพื่อสะท้อนการทำงานจริง

## ขอบเขตที่เสนอ

| ID | ความสามารถ | เกณฑ์รับงาน |
|---|---|---|
| MVP-01 | สมัคร เข้าสู่ระบบ ออกจากระบบ และจัดการบัญชี | ผู้ใช้เข้าถึงได้เฉพาะข้อมูลตนเอง รวมถึงการเรียก API โดยตรง |
| MVP-02 | ตั้งทุน โปรไฟล์ ความถี่ถอน และสัดส่วนแบ่งกำไร | ตรวจค่าบวก ขอบเขตเปอร์เซ็นต์ และผลรวมสัดส่วนเท่ากับ 100% |
| MVP-03 | สร้างแผนรายวัน | แสดงทุนฐาน งบต่อวัน risk ต่อไม้ จำนวนไม้ เป้าหมาย และเวอร์ชันกฎที่ใช้ |
| MVP-04 | ตรวจความเสี่ยงก่อนบันทึกไม้ใหม่ | ไม่อนุญาตสถานะแผนพร้อมเทรดเมื่อ risk เกินงบ ไม้ครบ หรือถึงเงื่อนไขหยุด พร้อมเหตุผล |
| MVP-05 | บันทึกไม้และผล | รองรับเปิด/ปิด/ยกเลิก รายการย้อนหลัง ค่าธรรมเนียม และการแก้ไขที่มีประวัติ |
| MVP-06 | Stop Trading | หยุดการเสนอไม้ใหม่เมื่อถึง loss limit, target หรือจำนวนไม้สูงสุด และยังบันทึกผลจริงได้ |
| MVP-07 | สรุปรายวันและประวัติ | ยอดทุน กำไรสุทธิ ขาดทุน จำนวนไม้ และงบคงเหลือตรงกับรายการต้นทาง |
| MVP-08 | Profit Router | แสดงยอดที่แบ่งได้ ให้ผู้ใช้ยืนยัน และป้องกันการกดซ้ำหรือแบ่งกำไรเดิมซ้ำ |
| MVP-09 | แผนถอนและกันกำไร | แสดงรายการถึงกำหนดในแอป ให้ผู้ใช้บันทึกว่าทำจริงแล้ว ไม่อ้างว่ามีการโอนเงิน |
| MVP-10 | ภาพรวมระยะยาวแบบบันทึกเอง | เห็นยอดที่กันไว้ ยอดที่บันทึกว่านำไปลงทุน และเงินเหลือ โดยไม่ซ้ำกัน |
| MVP-11 | AI Assistant ด้านความเสี่ยง | ตอบจากแผนและรายการของเจ้าของบัญชี ระบุเวลาของข้อมูล และไม่เปลี่ยนเพดานจากคำสั่งในแชต |

Stop Trading ควบคุมได้เฉพาะแผนและคำแนะนำในแอป ไม่สามารถหยุดการเทรดบนแพลตฟอร์มภายนอกได้ หากผู้ใช้เทรดต่อ ต้องบันทึกผลจริงและติดธงละเมิดแผนได้

## สิ่งที่เลื่อนไประยะถัดไป

- รับข้อมูลโบรกเกอร์อัตโนมัติ ส่งคำสั่งซื้อขาย และบอทซื้อขาย
- ข้อมูลตลาดสด ข่าว sentiment และ AI ที่จัดอันดับหรือเลือกหุ้นเฉพาะบุคคล
- คะแนน Growth/Value/Risk/Quality และ confidence เชิงตัวเลข จนมีข้อมูลและวิธีประเมินรองรับ
- Script Marketplace, การรับชำระค่าสมาชิก และรายได้พันธมิตร
- Rebalancing อัตโนมัติ การแจ้งเตือนนอกแอป และการวิเคราะห์พฤติกรรมเชิงลึก

## กฎคำนวณที่เสนอ

ใช้จำนวนเงินเป็นจำนวนเต็มหน่วยสตางค์ ไม่ใช้ floating point สำหรับบัญชี สัดส่วนใช้หน่วยที่กำหนดแน่นอน เช่น basis points

1. กำหนดทุนฐานตอนเริ่มวัน และบันทึก snapshot นโยบาย การเพิ่มทุนหรือเปลี่ยน risk ระหว่างวันไม่เพิ่มงบของแผนเดิมโดยอัตโนมัติ
2. `dailyBudget = floor(capitalBase × dailyRiskRate)`
3. `realizedNetPnL = ผลรวมกำไร/ขาดทุนที่ปิดแล้วหลังหักค่าธรรมเนียม`
4. `lossConsumed = ผลรวมขนาดผลขาดทุนสุทธิของไม้ที่ปิดขาดทุน` โดยไม่หักกลบด้วยไม้กำไร ตามนโยบายที่เสนอ
5. `remainingRisk = max(0, dailyBudget − lossConsumed − openRiskReserved)`
6. จำนวนไม้สูงสุดเริ่มต้น `min(configuredTradeCap, floor(dailyBudget / riskPerTrade))` ต้องปฏิเสธ risk ต่อไม้เป็นศูนย์หรือค่าติดลบ
7. จำนวนไม้ที่ยังวางแผนได้ต้องตรวจทั้งเพดานจำนวนไม้ที่ใช้ไปและงบคงเหลืออีกครั้งทุกครั้ง
8. Risk ต่อไม้คือขาดทุนสูงสุดที่ประเมินรวมต้นทุน ไม่เท่ากับยอดซื้อเสมอไป หากประเมินไม่ได้หรือขั้นต่ำของแพลตฟอร์มเกินงบ ให้แสดงว่าไม่สามารถสร้างแผนที่เข้ากับข้อจำกัดได้
9. กำไรที่เกิดขึ้นไม่เพิ่ม dailyBudget ในวันเดียวกัน และ AI ไม่มีสิทธิเปลี่ยนค่าจากสูตร
10. ถ้ากำหนด dailyTarget ให้หยุดเสนอไม้เมื่อกำไรสุทธิถึงเป้า ห้ามคำนวณจำนวนไม้เพิ่มเพื่อไล่เป้า เป้าหารจำนวนไม้เป็นเพียงตัวเลขประกอบ ไม่ใช่ผลตอบแทนคาดการณ์

สูตรขาดทุนสูงสุดเป็นการประเมิน ไม่สามารถรับรองผลจริงในกรณี slippage หรือขาดทุนเกินแผนได้ ระบบต้องรองรับการบันทึกขาดทุนจริงที่มากกว่างบ

```text
อ่านแผนรายวันและรายการที่ยืนยันแล้ว
คำนวณกำไรสุทธิ ขาดทุนสะสม ความเสี่ยงไม้ค้าง และจำนวนไม้
ถ้าขาดทุนสะสม >= งบรายวัน: STOP_LOSS
ถ้าตั้งเป้าหมายและกำไรสุทธิ >= เป้าหมาย: STOP_TARGET
ถ้าจำนวนไม้ถึงเพดาน: STOP_TRADE_CAP
ถ้างบคงเหลือ < risk ของไม้ถัดไป: INSUFFICIENT_BUDGET
นอกเหนือจากนั้น: PLAN_AVAILABLE
บันทึกเหตุผลและข้อมูลที่ใช้ตัดสินใจ
```

สถานะหยุดควรคงอยู่จนจบวัน การแก้รายการผิดต้องคำนวณใหม่พร้อมประวัติและเหตุผล ไม่เปิดแผนใหม่เพียงเพราะรีเฟรชหน้า เมื่อข้ามวัน ไม้ที่ยังเปิดต้องไม่ทำให้ risk หายไป นโยบาย MVP ที่เสนอคือกันความเสี่ยงไม้ค้างต่อในแผนวันใหม่

## การแบ่งกำไรและบัญชี

- กำหนดรอบบัญชีและยอดกำไรสุทธิสะสมหลังชดเชยขาดทุนก่อนหน้าให้ชัดก่อนพัฒนา Router
- ยอดแบ่งได้ต้องไม่เกินกำไรสุทธิที่ยังไม่เคยแบ่ง และไม่เกินเงินที่บันทึกว่าเหลือให้จัดสรรจริง
- หากยอดแบ่งได้เป็นศูนย์หรือติดลบ ไม่สร้างรายการแบ่งกำไร
- คำนวณสามส่วนในสตางค์ ปัดลงสองส่วนแรกและให้ส่วนสุดท้ายรับเศษ เพื่อให้ผลรวมเท่าต้นทางเสมอ
- การจัดสรรคือการกันเงิน การยืนยันถอนจริงหรือซื้อระยะยาวจริงเป็นอีกเหตุการณ์หนึ่ง ห้ามนับเป็นกำไรใหม่
- การย้ายเงินระหว่างหมวดไม่เพิ่มสินทรัพย์รวม ฝาก/ถอนทุนต้องแยกจากกำไรขาดทุน
- ใช้ transaction และ idempotency key ป้องกันการแบ่งหรือบันทึกซ้ำจากการกดหลายครั้ง
- หากแก้ผลเทรดที่แบ่งกำไรแล้ว ให้ทำรายการปรับปรุงอ้างอิงรายการเดิมและแจ้งยอดขาดจัดสรร ห้ามลบประวัติหรือทำเหมือนเรียกเงินที่ถอนแล้วกลับมาได้

## หน้าจอขั้นต่ำ

1. บัญชีและตั้งค่าเริ่มต้น
2. Dashboard: ทุน แผนวันนี้ งบเหลือ สถานะหยุด และรายการถึงกำหนด
3. แผนความเสี่ยงและบันทึกการเทรด
4. ประวัติและสรุปผล
5. แบ่งกำไรและแผนถอน
6. เงินระยะยาวและรายการลงทุนที่ผู้ใช้บันทึก
7. AI Assistant

## ข้อมูลหลักที่เสนอ

| Entity | ข้อมูลสำคัญ |
|---|---|
| User / Settings | เจ้าของบัญชี timezone สกุลเงิน การตั้งค่า |
| RiskProfile / RiskPolicyVersion | preference กฎ เพดาน วันที่มีผล |
| DailyPlan | วันที่ ทุนฐาน budget target trade cap snapshot policy สถานะหยุด |
| Trade | สินทรัพย์ แพลตฟอร์ม กลยุทธ์ จำนวนเงิน planned risk สถานะ เวลา |
| TradeResult / Revision | ผลสุทธิ ค่าธรรมเนียม เวลาปิด เหตุผลแก้ไข |
| LedgerEntry | เงินเข้าออก/ย้ายหมวด แหล่งที่มา เงินสตางค์ idempotency key |
| ProfitAllocation | รอบกำไร สัดส่วน snapshot ยอดสามส่วน อ้างอิง ledger |
| WithdrawalPlan / WithdrawalRecord | รอบ วันครบกำหนด สถานะ และวันที่ผู้ใช้ยืนยัน |
| LongTermHolding / Transaction | สินทรัพย์ หน่วย ต้นทุน ซื้อ/ขายที่บันทึกเอง |
| AssistantConversation | เจ้าของ ข้อความ ข้อมูลอ้างอิงและเวลา |
| AuditEvent | ผู้กระทำ เหตุการณ์ เวอร์ชัน ค่าเดิม/ใหม่ โดยไม่เก็บ secret |

ทุกข้อมูลส่วนตัวต้องเชื่อม owner ID และตรวจสิทธิ์ฝั่งเซิร์ฟเวอร์ ราคาพอร์ตที่กรอกเองต้องแสดงเวลาประเมิน หากไม่มีราคาให้แสดงต้นทุน ไม่อ้างเป็นมูลค่าตลาดล่าสุด

## คุณภาพและข้อจำกัด

- Risk Engine ต้องทำงานได้แม้ AI ล่ม และเป็นแหล่งตัวเลขหลักของระบบ
- AI ต้องไม่สร้างราคา ยอดบัญชี โอกาสชนะ หรือข้อมูลตลาดที่ไม่มีแหล่งรองรับ หากข้อมูลไม่พอให้บอกว่าขาดอะไร
- แยกข้อมูลตัวอย่างจากข้อมูลบัญชีจริงอย่างเห็นได้ชัด
- ตรวจสิทธิ์ทุกคำขอ เก็บกุญแจบริการฝั่งเซิร์ฟเวอร์ และไม่บันทึกข้อมูลลับใน log
- รองรับข้อมูลผิดรูป รายการซ้ำ การส่งคำขอพร้อมกัน และรอยต่อวันตาม timezone
- กำหนดวิธีสำรอง/กู้คืน การลบบัญชี และขอบเขตข้อมูลที่ส่งให้ AI ก่อนเปิดให้ผู้ใช้จริง
- UI ภาษาไทยใช้งานบนมือถือได้ และอธิบายเหตุผลของสถานะหยุดอย่างตรงไปตรงมา

## สถานการณ์ยอมรับสำคัญ

ใช้ตัวเลขต่อไปนี้เป็น test fixture เท่านั้น ไม่ใช่นโยบายแนะนำ:

- ทุน 350 บาท risk รายวัน 5% risk ต่อไม้ 5 บาท ได้ budget 17.50 บาท และจำนวนไม้เริ่มต้น 3 ไม้
- แพ้สองไม้ ไม้ละ 5 บาท ไม่มีไม้ค้าง เหลือ budget 7.50 บาท และโควตา 1 ไม้
- เมื่อมีไม้ค้าง risk 5 บาท ต้องหักออกจากงบที่พร้อมใช้ และไม่อนุญาตจองงบซ้ำด้วยคำขอพร้อมกัน
- ไม้กำไรไม่คืนงบขาดทุนสะสม เมื่อครบจำนวนไม้ยังหยุดแม้งบเหลือ
- ขาดทุนจริงเกินเพดานต้องบันทึกได้และแสดงสถานะหยุด
- กำไรถึง target หยุดการเสนอไม้ต่อ และสถานะไม่หายเมื่อโหลดหน้าใหม่
- แบ่งกำไรที่มีสิทธิแบ่ง 100 บาทด้วย 50/30/20 ได้ 50/30/20 บาท การส่งคำขอซ้ำไม่สร้างยอดเพิ่ม
- ขาดทุนค้างจากรอบก่อนต้องถูกพิจารณาก่อนคำนวณกำไรที่แบ่งได้
- กรณีเศษสตางค์ ยอดสามส่วนรวมเท่าต้นทาง และยอดที่กันแล้วไม่ถูกนับซ้ำตอนยืนยันถอน
- ผู้ใช้คนหนึ่งอ่านหรือแก้รายการของอีกคนไม่ได้ แม้เปลี่ยน ID ในคำขอ
- AI ใช้งานไม่ได้ยังดูแผน บันทึกผล และแบ่งกำไรได้
